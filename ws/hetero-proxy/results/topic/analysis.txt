== T1: training-size NCCL collectives while host<->GPU copies run (scripts/topic/t1_bigcoll_pcie_v1.py, run_t1_v1.sh)
Method: torchrun 8 ranks; per round every (op, size, mode) window once in shuffled order (same order on all ranks), 30 rounds;
window = barrier, side stream enqueues 16 MiB pinned-host copies (NUMA-local, cudaHostAlloc via torch) that outlast the
collectives, main stream 2 warm-up + 10 timed calls between CUDA events; per-call time = rank-max; ratio paired with the
same round's no-copy window (median, p10/p90 in t1_summary.txt). Copy rate during collectives from per-chunk events.
size = full tensor per rank (all_reduce input, reduce_scatter input, all_gather output), bf16.

  Absolute time under d2h (ms, no-copy x ratio): best protocol flips with traffic.

  Without copies NCCL's default (Simple) is the faster one at >= 16 MiB, so NCCL's choice is wrong only while copies run.

== T2: RoCE loopback on the GPU0/GPU1 switch (NIC 1d:00.0/.1 = mlx5_0/mlx5_1) (scripts/topic/t2_rdma_paths_v1.sh)
Method: ib_write_bw client and server on the same port (NIC reads source, writes destination), 1 MiB messages, 4 s,
tclass 104, 5 rounds shuffled; background GPU->host copies from t2_copy_bg_v1.py (rate over the middle of its run).
All 5 rounds within 1% of each other.
  A host -> host, 1 port                               100.8 Gb/s   (anchor ib_write_bw host 98.05: ok)
  B GPU0 -> GPU1 (NIC reads GPU), 1 QP                  47.9 Gb/s
  C same, 8 QPs                                         48.4 Gb/s   -> read cap is not per-QP
  D host -> GPU1                                        97.4 Gb/s   -> host-sourced send at line rate when the uplink is idle
  E host -> GPU1 + GPU0/GPU1 copying to host            30.5 Gb/s   (copies 21.5 GB/s total)
  F 2 ports host -> GPU + GPU0/GPU1 copying to host     22.9 + 22.7 Gb/s (copies 21.1 GB/s)
  G 2 ports GPU -> GPU (NIC reads GPU), 1 QP            29.9 + 29.9 Gb/s = 7.5 GB/s per switch
  H same, 8 QPs                                         31.4 + 31.4 Gb/s
  I GPU0+GPU1 copying to host only                      26.2 GB/s total
  -> A NIC reading host memory collapses (97 -> 30 Gb/s) while the GPUs on its switch write to host; staging sends
     through host memory is not a free win. Inference (not verified): NIC read requests wait behind the GPUs' posted
     writes in the same upstream direction (PCIe ordering) or in switch arbitration.
  Anchor deviation: B 47.9 vs E4 cross-node 56 Gb/s (-14%); G 7.5 GB/s per switch vs E4 9.5 (-21%). Loopback makes the
    same NIC and switch also carry the destination writes; do NOT quote T2 GPU-read numbers as cross-node numbers.

== T3: Flux fused kernels vs NCCL+cuBLAS under GPU->host copies (scripts/topic/t3_flux_vs_hostcopy_v1.py; t3_v1/)
Method: ./launch.sh (8 ranks), CUDA_DEVICE_MAX_CONNECTIONS=8, eager; Qwen2.5-32B layer shapes, TP8 + sequence parallel,
M = 4096 tokens; Flux AG = All2All + use_read; same window / pairing as T1, 30 rounds; d2h8 = all 8 GPUs copy,
d2h2 = GPU0+GPU1 only. Fused output == NCCL path (allclose 0.05) on all ranks. Guard CLEAN. 1-5 windows per item dropped
for SM clock < 95% of modal 1410 MHz.
  item (per call)       none ms   d2h8          d2h2       | fused advantage (nccl/fused) none -> d2h8
  AG gate_up fused      1.198     x1.11 1.331   x1.10      |
  AG gate_up nccl+mm    1.264     x1.23 1.556   x1.22      | 1.06 -> 1.17
  AG qkv fused          0.335     x2.12 0.711   x2.13      |
  AG qkv nccl+mm        0.459     x1.65 0.757   x1.61      | 1.37 -> 1.06
  RS down fused         0.629     x1.07 0.675   x1.06      |
  RS down mm+nccl       0.767     x1.36 1.043   x1.33      | 1.22 -> 1.55
  RS o_proj fused       0.260     x1.21 0.313   x1.25      |
  RS o_proj mm+nccl     0.368     x1.72 0.632   x1.66      | 1.42 -> 2.02
  GEMM alone            x1.00-1.09 (copies barely touch the GEMM)
  -> When the GEMM is long (gate_up, down), Flux's tile overlap keeps the slowed communication under the GEMM

     exposed and Flux is hurt MORE than NCCL (x2.12 vs x1.65). Flux waits/releases every tile with system-scope

  Anchors: NCCL AG 40 MiB = nccl+mm - mm = 0.249 ms -> 147 GB/s busbw, between T1 AG 32 MiB (140) and 64 MiB (176): ok.
           mm gate_up 290 GFLOP / 1.015 ms = 286 TFLOPS (92% of 312 peak; high but plausible for this large GEMM).
