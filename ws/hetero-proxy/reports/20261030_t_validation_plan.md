# 題目 T 的驗證計劃與事前登記（2026-10-30，跑任何實驗之前寫入並提交）

題目 T：訓練時主機↔GPU 搬運（offload）拖慢 NVLink 集合通訊 → 量測＋干擾模型＋排程器（`20261030_topic_search.md` 第 5、5.7 節）。
使用者要求：先做足夠的實驗，確認整體值得投入，再開始規劃。只用 css-host-158。

## 要回答的四個問題（各自可以否決題目）

| # | 問題 | 為什麼可能否決 |
| --- | --- | --- |
| Q-A | 在真實的訓練步驟裡，干擾佔一步多少時間？ | offload 常常本身就卡在 PCIe（搬得比算得久），那時通訊變慢藏在搬運底下，不影響步驟時間 |

## 實驗

全部在 `exclusive_guard_v2.py` 內、tmux、打亂交錯、同輪成對比較、記錄 SM 時脈。

**V1 機制旋鈕（T1 探針 v2，op 層級）**
- V1a 搬運節拍：d2h 以 4 MiB 小塊、工作比例 25 / 50 / 100%（塊之間 GPU 端 sleep），量 16 / 32 / 64 MiB 的 RS / AR。
- V1b 通道數：`NCCL_MIN_NCHANNELS=32`、`NCCL_MAX_NCHANNELS=4` 各一次，同上大小（含 128 / 256 MiB，看大訊息有沒有代價）。
- 預測：V1a 25% 工作比例時減速仍 ≥ 全速減速的一半（每一小塊都會把上行線瞬間塞滿）；V1b 通道越多越不敏感（16 MiB ≤ ×1.5）、通道越少越敏感。

**V2 最新 NCCL（2.32.3，pip 安裝到 `~/opt/nccl-2.32.3`，以 LD_PRELOAD 套到 torch 2.6）**
- T1 預設與 LL128 再跑一次。預測：仍有 ×1.5 以上（16–32 MiB、Simple、d2h）。

**V3 訓練步驟原型（主實驗）**
- 自寫 TP8＋序列平行（Megatron 式）的 Qwen2.5-32B 層（hidden 5120、40 頭 / 8 KV 頭、FFN 27648；每卡 5 頭 / 1 KV 頭 / 3456），
  8 層，前向＋反向，自寫 autograd（AG ↔ RS 對偶、dgrad / wgrad 分開，每個 GEMM 與通訊前後可插事件），flash attention；先與 PyTorch 自動微分的參考版比對梯度。
- 序列長度（每個 micro-batch 的 token 數）：2048 / 4096 / 8192。
- 兩種 offload 情境：
  - **S-G 梯度 offload**（ZeRO-Offload 式）：每層權重梯度一算好就搬到主機（每卡每層 122 MB）。
  - **S-A activation offload**：前向時把每層的一部分存檔（例如 gate_up 的輸入）搬到主機、反向前一層提前搬回；搬多少依「前向時間 × 搬運速度」選，不讓搬運本身變成瓶頸。
- 做法（每輪交錯）：none（不搬）、naive（就緒就搬，現行框架做法）、serial（反向結束後才搬）、window（**排程原型**：用量好的每個運算時間，只在沒有集合通訊的窗口放行剛好放得下的塊，GPU 端事件觸發）。
  另一個程序以 `NCCL_PROTO=LL128` 重跑 none / naive（「只改設定」的對照）。
- 下界（理想）：LB = max(none 的步驟時間, 搬運單獨所需時間)。干擾損失 = naive − LB。
- 預測：S-G 在 2048 時被 PCIe 卡住（損失 < 5%），4096 / 8192 損失 5–15%；S-A 損失 10–25%；window 收回 ≥ 50%；LL128 收回 30–60%。

**V4 推到整個模型（分析，不量新東西）**：用 V3 每層數字推 64 層、梯度累積 1 / 4、加上 CPU Adam 時間範圍（用 M0 的 CPU 讀取速度估），算干擾佔整步的比例。標為推論。

**V5 文獻再查**：針對 2025–2026 的論文／預印本，查「offload / PCIe 搬運 × 集合通訊干擾」與「融合 kernel × offload 排程」。

## 判定規則（事前登記）

**值得做（GO）**：下面四條都成立。
1. Q-A：至少一個真實情境（V3 的某個序列長度 × S-G 或 S-A）naive 比下界慢 ≥ 10%。
2. Q-B：最好的「只改設定」做法（LL128、通道數、新版 NCCL 中最好者）仍留下 ≥ 5% 的步驟時間，或在別的大小上有代價（例如大訊息變慢 ≥ 10%）。
3. Q-C：window 原型收回 ≥ 50% 的損失。
4. Q-D：最新 NCCL 仍有 ≥ ×1.5（16–32 MiB），且查不到做同一件事的論文。

**不值得（NO-GO）**：第 1 條不成立（所有情境 < 5%）或第 4 條不成立 → 改做備案 F（fusion-dispatch 成文）。
**介於之間**：寫明哪一條差多少，交使用者決定。
